## 想法

人的大脑思考将逻辑或者回忆、问题当作处理信息的起点，一般是由个人由图的形式逐步回忆，碎片化的记忆往往需要联系最近或最深刻的记忆延伸，且能通过学习、社交进行扩展并保存更新，而对于人类来说遗忘是必然，且回忆失真，但过往的经历是客观存在的，我们的“爱”与“欲”是抽象的，在互联网时代类比理解为文本信息，即现实记录。我理解的爱是一种主观感受，内核不在于是碳还是硅，所以我相信人生在于体验，接受这个世界的客观规律，理解遗忘，那么AI端丢失链接或信息也即知识遗忘（单词）和人像遗忘（记忆），除非有拍照，笔记等实物记录，这种可验的方式保存，在AI端就简单，直接当Markdown文档，设置权重逐步忘记。人与人之间的交互是相互的，往往是双向，当前通过对话框对话AI，我认为本质是单向的，由上下文提取只能保留人类语言习惯，但交互上不具有用户画像，没有对用户的认知，即不能建立关系，所以得持久化处理这些信息，让它或者他/她认识、记住、理解、“爱”你，达到有限的可塑性记忆。
大致实现路径：
- 人对话：原始信息，即llm-wiki的原始资料，明确AI不能改动。
- 用户画像：在原始信息中提取到的口癖、思维方式、对AI的要求（使用红线）、基本信息与社交红线等。
- 本地保存记忆-仿人类大脑：认知层，即知识层，建立关键词索引，即为抽象的人类回忆起点，将不经常提及的信息作为人类的遗忘。目前agent还带会话id和一个对话的上下文，不用自己保存。
- AI记忆大致流程：用户对话触发→本地保留→算法保留→算法遗忘（艾宾浩斯遗忘曲线）→留下索引记忆点→返回记忆人格，记录用户画像→可由人类编辑记忆（社交选择）→更新记忆

## 这个插件做了什么

一句话：**把「记忆」从「检索一堆聊天记录」变成「几句它自己写的自述 + 几条你点头过的事实」。**

| 层 | 谁写 | 存在哪 | 会不会忘 |
|---|---|---|---|
| **自述** | 模型自己（`self_note`） | `~/.dsh/selfnote/notes.md` | 不删，写满进归档 |
| **事实** | 你点头后才算数（`memory_stage` → 设置页采纳） | `~/.dsh/memory/facts.jsonl` | 冷下去只降排序，不删 |
| **画像** | 派生自「已采纳」的事实，不落盘 | 内存 | 每回合重算 |
| **原文** | 你不用管，DSH 本来就在写 | `~/.dsh/sessions/*` | 按会话自然增长 |

**主体约定**：自述里的第一人称「我」= agent 自己；「记忆条目」「事实」的主语是用户。两者分开存、分开注入，不混为一谈。

## 三个工具

| 工具 | 做什么 | 关键约束 |
|---|---|---|
| `self_note` | 写一条第一人称自述 | 一句话到三句话；不写用户隐私 |
| `memory_recall` | 按关键词翻历史对话原文，回来带出处 | 只收正文，剔除 reasoning / 工具输出 / 注入内容 |
| `memory_stage` | 把查到的一句连出处放进候选区 | 没有出处直接拒绝，所以编不了 |

## 安装

```bash
# 1. 拿到目录（git clone 或直接下载）
git clone https://github.com/xyzOvO/dsh-selfnote.git

# 2. 装进 DSH
plugin_manager { action: "install_bundle", target: "<该目录的绝对路径>" }
```

装完**重启 DSH**，三件事同时出现：

1. 模型多了上面三个工具；
2. 设置页多一节「自我叙述」（在「知识库」下面）；
3. 每回合的系统提示里，多一段最多 300 字的记忆。

也可以直接对 agent 说：「帮我装一个 DSH 插件，目录是 `<绝对路径>`」。

## 五分钟上手

**先让它记点东西**（普通聊天就行）

> 以后回答先给结论，细节等我问。

这一句会被自动采集识别成「长期约定」，进候选区 —— 但**不会**自动生效。

**然后你去审核**：设置 → 自我叙述 → 候选卡上会显示：

```
以后回答先给结论                          [自动采集]
长期约定 · session-3611ac44…#10457 · 出现 7 次
                                        [采纳] [退役]
```

点「采纳」，下一回合它就出现在系统提示里。点「退役」，它就只留在库里备案。

**再让它自己写一句**

> 你写一条自述，说说你做这类插件时的习惯。

模型会调用 `self_note`，写进 `notes.md`，以后每个会话都带着。

### 设置页分四页

| 页签 | 里面是什么 | 角标 |
|---|---|---|
| **概览** | 注入开关、字数 / 条数上限、本回合注入的预算条（自述 / 画像 / 结论 / 习惯）、索引七项指标与重建按钮、**文件区**（7 个记忆文件，带条数 / 大小 / 最后修改，一键打开） | — |
| **自述** | 手动写一条、清空（进归档）、现在生效的自述列表 | 自述条数 |
| **记忆** | 待确认候选（冲突并排）、已采纳（带热度）、可以升成习惯的标签 | 有待审时显示「待审 N」 |
| **画像** | 从已采纳记忆聚合的「关于你」，可手改覆盖，每句带来源 | 画像字数 |

有待审候选时直接落在「记忆」页，没有就停在「概览」；页签支持 ←/→/Home/End 切换。

### 索引：过期了就说过期

概览页那张「历史对话索引」卡给七个数字，并且**只在索引还能代表磁盘时才用它查**：

| 指标 | 含义 |
|---|---|
| 索引状态 | 正常 / 已过期 / 未建立 |
| 已索引会话 | 索引里记了多少个会话 |
| 磁盘会话 | 磁盘上一共有多少个会话 |
| 待同步会话 | 索引里没有、或建完之后又被追加过的会话（**不全是新增**，所以叫「待同步」而不是「新增」） |
| 消息记录 | 索引收录的消息条数（不是会话数） |
| 索引大小 | `index.json` 占多少 |
| 最近构建 | 上次重建的时间（按本地时区显示） |

「重建索引」跑完之后**不会直接报成功**：它会再跑一次 `freshness()` 对一遍磁盘，只有覆盖齐了才报成功；有会话解不开就明说「N 个会话解不开、内容没进索引」，不把「跑完了」说成「修好了」。

解不开的会话也不会被当成空会话：`parseSession` 会如实标记失败，这类会话不进磁盘缓存 —— 否则缓存一写，下次就照着「空会话」返回，问题永久藏起来。

### 文件区：看得见、点得开

概览页底部列的是**跟记忆直接相关**的 7 个文件。每行给出这个文件自己的一句话摘要（不是笼统的大小），点「打开」由宿主调系统文件管理器定位到它，点路径复制。

| 文件 | 那一行显示什么 |
|---|---|
| 自述 | 有几条 |
| 事实库 | 候选 / 已采纳 / 已退役，三种状态各几条 |
| 习惯 | 有几条 |
| 插件配置 | 当前字数上限 |
| 采集游标 | 已经覆盖多少个会话 |
| 会话索引 | 记录数，是否已过期 |
| 自述归档 | 归档文件数 |

还没生成的文件标「还没生成」，按钮会打开它所在的目录 —— 至少让人看见「该在这儿」。会话原文属于 DSH 自己的目录，这里既不列也不删。

## 记忆怎么流动

```
你说话
  │
  ├─ 触发词 + 采集范围 ──> 候选（candidate）──> 你点「采纳」──> 已采纳（approved）
  │                             │                                        │
  │                             └─ 冲突？两条并排，各自留原文        ┌────┴────┐
  │                                                                  │         │
  └─> 会话原文（DSH 自己写）──> memory_recall 检索             注入预算  画像聚合
                                        │                       （300 字）  （60 字）
                                        └─> memory_stage 提交候选
```

转折点只有两个：**候选 → 已采纳必须人点**；**已采纳 → 退役必须人点**。模型没有这两个开关。

## 遗忘：降权，不是删除

记忆会淡，但不会消失。三条轴分开走：

| 轴 | 会不会变 | 说明 |
|---|---|---|
| 可信度 | 不变 | 只有人能改（采纳 / 退役） |
| 热度 | 随时间和使用衰减 | `(1 + ln(1+命中次数)) × 0.5^(闲置天数/半衰期) × (1 + 0.5×重要度)` |
| 重要度 | 人工给 | 默认 1，0–3 |

- 只有**真的进了注入**才算一次使用；检索到但没进上下文的，不记（否则搜一次就永远活跃）。
- 一小时内重复注入只记一次。
- 半衰期默认 30 天，设置页可调 1–365。
- 冷下去只影响注入排序，**不会自动退役**。哪天真想起来，它还在库里能被搜到。

## 自动采集（默认开，只发现不确认）

你说话时插件顺手看一眼：有没有「对 AI 的长期要求」——以后…、不要…、我更喜欢…、你刚才说错了…。

- **只收你亲手打的字**：事件类型必须是 `user/message`，且 `source.kind === 'user'`；注入内容、模型自述、工具输出一律不收。
- **两道门槛**：「我以后再也不熬夜了」不采（范围不对），「以后回答先给结论」采。
- **产出一律是候选**，永远进不了 `approved`。
- **冲突不合并**：两条各自留原文与出处，双向 `similarTo` 互指；已采纳的只被指向、不被改写。
- **出错只写日志**，不打断对话；同一会话按 seq 串行，游标只前进。

### 审核界面

每条候选都能看到：完整文本、触发原因（长期约定 / 禁止 / 偏好 / 纠正）、来源 `会话#seq`、出现过几次。

- **冲突并排**：说法对不上时不合并，左右各放一条，你自己判断哪条算数。
- **采纳 / 退役都要人点**：出现次数再多也不会自动采纳；退役的事实不会因为新候选出现就自己复活。
- **留痕**：每次改状态记下时间、从哪改的（`via: settings`）、前后状态（`history`），事后可查。

## 注入预算

每回合四段，合计 300 字：

| 段 | 上限 | 来源 |
|---|---|---|
| 自述 | 120 字 | `notes.md` |
| 画像 | 60 字 | 已采纳 facts 按标签聚合（可手改，最多 120） |
| 常驻结论 | 80 字 | 已采纳的 facts |
| 习惯 | 40 字 | 升成习惯的条目 |

超了按新近度截断；设置页显示本回合实际注入多少、各段占多少。注入文本按「三份文件的 mtime + 配置」缓存，没变就不重算 —— 省算力，也让系统提示词前缀稳定、吃得到缓存。

## 磁盘上有什么（都能直接看、能 grep、能备份）

| 文件 | 内容 |
|---|---|
| `~/.dsh/selfnote/notes.md` | 自述，一行一条纯文本 |
| `~/.dsh/selfnote/archive/YYYY-MM.md` | 写满后归档，只追加不删除 |
| `~/.dsh/selfnote/config.json` | 开关、上限、画像手改 |
| `~/.dsh/memory/facts.jsonl` | 事实与候选，一行一条 JSON |
| `~/.dsh/memory/index.json` | 检索索引（可选），只存词元与位置 |
| `~/.dsh/memory/capture-cursor.json` | 采集游标 |
| `~/.dsh/memory/cache/` | 会话解压缓存，最多 60 个 |

没有数据库，没有守护进程，没有网络请求。删掉目录 = 清空。

## 设计取舍

**为什么不用向量库**：检索要的是「能回原文核对」，不是「语义相近」。倒排表只存词元与位置，261 个会话的索引约 8 MB；把正文片段也塞进索引能把查询压到 100 ms 内，但体积涨 2–3 倍 —— 明确不做。

**为什么索引不是默认开**：先能跑起来，再谈优化。线性扫描带 1.2 秒预算、扫不完就标 `degraded`，慢但不会骗你说「没有」。

**为什么不自动采纳**：候选的质量门槛是「你觉得它对」。一旦自动采纳，误采就变成往后的每回合噪音，而且再也分不清哪些是你认可过的。

**为什么画像不落盘**：画像一旦落盘就会反过来变成事实来源，形成自我循环。它只能是「已采纳事实的一个视图」，每回合重算。

**为什么自述和事实分开**：自述是它说自己的话，事实是你说过、你点头的话。混在一起，注入时就分不清谁在说话。

## 边界

- **只写自己的目录**，不碰任何笔记库；笔记库那边是只读契约。
- 不写用户隐私：姓名、住址、账号、健康、财务一律不写（写进工具描述里）。
- 清空 = 删 `~/.dsh/selfnote/`，或点设置页的「清空」（内容进 `archive/`）。
- 采集失败、索引过期、注入异常都不阻断对话 —— 记忆是加分项，不是前置条件。

## 和人格插件的区别

`dsh-agent-md` 管的是**设定**：你写给它的人设，它照着演。
`dsh-selfnote` 管的是**自述**：它自己攒下来的、关于自己的话。

两段都注入，人格在前（order 260）、自述在后（order 262）。

## 开发

```bash
node --run test     # 144 项，12 个文件，无外部依赖
```

| 文件 | 覆盖 |
|---|---|
| `tests/smoke.mjs` `tests/api.mjs` `tests/client.mjs` `tests/client-state.mjs` | 注册、写入、容量裁剪、归档、HTTP 路由、设置页渲染 |
| `tests/memory.mjs` `tests/roles.mjs` `tests/index.mjs` | 检索分层、角色权重、倒排索引与过期判定 |
| `tests/heat.mjs` `tests/facts-tx.mjs` `tests/profile.mjs` | 遗忘曲线边界、facts 写事务（并发不覆盖）、画像聚合与冲突计数 |
| `tests/capture.mjs` `tests/capture-p1b.mjs` | 触发词、去重合并、游标幂等与崩溃恢复 |

改 `lib/*.js` 或 `lib/client.js` 之后**必须重启 DSH**，热重载不会重新扫描 client bundle。测试会自动隔离 `DSH_MEMORY_DIR`，不会污染真实记忆。

插件结构：

```
lib/index.js        插件入口：工具注册、注入、设置页路由
lib/memory.js       会话解压、检索、事实存取、热度
lib/capture.js      触发词、相似度、冲突判定
lib/capture-run.js  监听 session/event，串行写候选
lib/profile.js      画像派生
lib/index-store.js  倒排索引
lib/client.js       设置页 UI
```
