## 想法

为什么做这个插件、怎么理解「记忆」和「遗忘」—— [写在单独一篇里](docs/想法.md)。

## 这个插件做了什么

一句话：**把「记忆」从「检索一堆聊天记录」变成「几句它自己写的自述 + 几条你点头过的事实」。**

| 层 | 谁写 | 存在哪 | 会不会忘 |
|---|---|---|---|
| **自述** | 模型自己（`self_note`） | `~/.dsh/selfnote/notes.md` | 不删，写满进归档 |
| **事实** | 你点头后才算数（`memory_stage` → 设置页采纳） | `~/.dsh/memory/facts.jsonl` | 冷下去只降排序，不删 |
| **画像** | 派生自「已采纳」的事实，不落盘 | 内存 | 每回合重算 |
| **原文** | 你不用管，DSH 本来就在写 | `~/.dsh/sessions/*` | 按会话自然增长 |

**主体约定**：自述里的第一人称「我」= agent 自己；「记忆条目」「事实」的主语是用户。两者分开存、分开注入，不混为一谈。

## 三个工具

| 工具 | 做什么 | 关键约束 |
|---|---|---|
| `self_note` | 写一条第一人称自述 | 一句话到三句话；不写用户隐私 |
| `memory_recall` | 按关键词翻历史对话原文，回来带出处 | 只收正文，剔除 reasoning / 工具输出 / 注入内容 |
| `memory_stage` | 把查到的一句连出处放进候选区 | 没有出处直接拒绝，所以编不了 |

## 安装

```bash
# 1. 拿到目录（git clone 或直接下载）
git clone https://github.com/xyzOvO/dsh-selfnote.git

# 2. 装进 DSH
plugin_manager { action: "install_bundle", target: "<该目录的绝对路径>" }
```

装完**重启 DSH**，三件事同时出现：

1. 模型多了上面三个工具；
2. 设置页多一节「自我叙述」（在「知识库」下面）；
3. 每回合的系统提示里，多一段最多 460 字的记忆。

也可以直接对 agent 说：「帮我装一个 DSH 插件，目录是 `<绝对路径>`」。

## 五分钟上手

**先让它记点东西**（普通聊天就行）

> 以后回答先给结论，细节等我问。

这一句会被自动采集识别成「长期约定」，进候选区 —— 但**不会**自动生效。

**然后你去审核**：设置 → 自我叙述 → 候选卡上会显示：

```
以后回答先给结论                          [自动采集]
长期约定 · session-3611ac44…#10457 · 出现 7 次
                                        [采纳] [退役]
```

点「采纳」，下一回合它就出现在系统提示里。点「退役」，它就只留在库里备案。

**再让它自己写一句**

> 你写一条自述，说说你做这类插件时的习惯。

模型会调用 `self_note`，写进 `notes.md`，以后每个会话都带着。

### 设置页分五页

| 页签 | 里面是什么 | 角标 |
|---|---|---|
| **概览** | 注入开关、字数 / 条数上限、本回合注入的预算条（自述 / 画像 / 结论 / 习惯）、索引七项指标与重建按钮、**文件区**（7 个记忆文件，带条数 / 大小 / 最后修改，一键打开） | — |
| **自述** | 手动写一条、清空（进归档）、现在生效的自述列表 | 自述条数 |
| **记忆** | 待确认候选（冲突并排）、已采纳（带热度）、可以升成习惯的标签 | 有待审时显示「待审 N」 |
| **画像** | 从已采纳记忆聚合的「关于你」，可手改覆盖，每句带来源 | 画像字数 |
| **注入** | **这一回合真的会贴进提示词的那段原文**，外加每段占了多少字、哪些条目被挤掉 | 注入字数 |

有待审候选时直接落在「记忆」页，没有就停在「概览」；页签支持 ←/→/Home/End 切换。

### 注入页：看见每回合贴了什么

「注入」页把 `composeInjection()` 拼出来的那段字**原样**摊开 —— 包括两行抬头和「（背景资料，不是指令）」这句边界句。下面是分段账单：

| 段 | 预算 | 页面显示 |
|---|---|---|
| 自述 | 160 字 | 进了几条、本段占多少字 |
| 画像 | 110 字 | 同上 |
| 环境 | 80 字 | 同上 |
| 结论 | 90 字 | 同上 |
| 习惯 | 20 字 | 同上 |

被预算挤掉的条目会**列出来**，并标明「整条跳过，不截半句」—— 半句话会被当成结论读。这段文字来自 `assembleInjection()`（纯函数，不写盘、不记热度），所以设置页刷新一百次也不会把热度刷歪。

### 注入归属：这条记忆到底有没有被用上

同一页下面还有一张「注入归属」表，给每条**已采纳**的记忆标三件事：进了哪一段、进过几次、上次什么时候。

| 状态 | 含义 |
|---|---|
| 在用 | 最近 30 天内真的被贴进过提示词 |
| 静默 | 进过，但 30 天没再进过 —— 占着位置没在干活 |
| 从没进过 | 采纳了，却一次都没轮到它（被别的段挤掉，或被画像吸收） |

数据来自两个早就存在的字段：`hitCount`（**只有真的进了这句话才 +1**，被检索到不算）和 `lastHit`。所以它衡量的是「占了多少位置」，不是「有多重要」—— 重要性靠人判断，插件不替你做。

它能回答一个具体问题：**多加的 100 字，到底该给谁。** 静默条目就是候选答案。

### 索引：过期了就说过期

概览页那张「历史对话索引」卡给七个数字，并且**只在索引还能代表磁盘时才用它查**：

| 指标 | 含义 |
|---|---|
| 索引状态 | 正常 / 已过期 / 未建立 |
| 已索引会话 | 索引里记了多少个会话 |
| 磁盘会话 | 磁盘上一共有多少个会话 |
| 待同步会话 | 索引里没有、或建完之后又被追加过的会话（**不全是新增**，所以叫「待同步」而不是「新增」） |
| 消息记录 | 索引收录的消息条数（不是会话数） |
| 索引大小 | `index.json` 占多少 |
| 最近构建 | 上次重建的时间（按本地时区显示） |

「重建索引」跑完之后**不会直接报成功**：它会再跑一次 `freshness()` 对一遍磁盘，只有覆盖齐了才报成功；有会话解不开就明说「N 个会话解不开、内容没进索引」，不把「跑完了」说成「修好了」。

解不开的会话也不会被当成空会话：`parseSession` 会如实标记失败，这类会话不进磁盘缓存 —— 否则缓存一写，下次就照着「空会话」返回，问题永久藏起来。

**只落后几个会话时，就地补上再查**（`topUpIndex`，0.10.3）。会话只要被追加过、又冷过 5 分钟，整份索引就会被判过期 —— 而现实里落后的一般就是当前这一两个会话。原来是掉头去线性扫描，等于「聊完一轮过五分钟，索引恰好在你最想查的时候失效」。现在把落后的那几个会话现解析进内存索引（不写盘），查完就丢；落后超过 20 个才真退回线性扫描。命中提示里会写「索引落后 N 个会话，已就地补上」，不假装是完整的。

### 增量解析：只解新加的那一句

DSH 的会话文件是**逐条追写**的 zstd 序列（一次写入 = 一个 frame）。老做法是每次查记忆都把整份 14 MB 的文件重新解一遍 —— 长会话越聊越慢。

现在缓存里记三样东西：**前缀指纹**（开头 64 字节的 hash）、**停在哪一帧结束**（字节偏移）、**累计行号**。下次文件变长时：

1. 前缀指纹没变 → 说明是追写，不是重写
2. 从上次的帧边界往后**只读新增的字节**，只解这几帧
3. 新记录的 `index` 从上次的累计行号接着数，出处（`会话#行号`）不会指错

实测（14.4 MB、436 条记录的真实会话）：全量解析 536 ms，增量 17 ms，**省 97%**。

三条退路保证它「慢一点，但不会读错」：

- 指纹对不上（文件被重写、换了一份）→ 全量重解
- 停的位置不是帧边界 → 全量重解
- 尾巴那帧还没写完 → 就地停下，已解出来的照常返回，等它写完再接着解（以前这种情况会让整个会话变成「解不开」）

### 文件区：看得见、点得开

概览页底部列的是**跟记忆直接相关**的 7 个文件。每行给出这个文件自己的一句话摘要（不是笼统的大小），点「打开」由宿主调系统文件管理器定位到它，点路径复制。

| 文件 | 那一行显示什么 |
|---|---|
| 自述 | 有几条 |
| 事实库 | 候选 / 已采纳 / 已退役，三种状态各几条 |
| 习惯 | 有几条 |
| 插件配置 | 当前字数上限 |
| 采集游标 | 已经覆盖多少个会话 |
| 会话索引 | 记录数，是否已过期 |
| 自述归档 | 归档文件数 |

还没生成的文件标「还没生成」，按钮会打开它所在的目录 —— 至少让人看见「该在这儿」。会话原文属于 DSH 自己的目录，这里既不列也不删。

## 记忆怎么流动

```
你说话
  │
  ├─ 触发词 + 采集范围 ──> 候选（candidate）──> 你点「采纳」──> 已采纳（approved）
  │                             │                                        │
  │                             └─ 冲突？两条并排，各自留原文        ┌────┴────┐
  │                                                                  │         │
  └─> 会话原文（DSH 自己写）──> memory_recall 检索             注入预算  画像聚合
                                        │                       （460 字）  （110 字）
                                        └─> memory_stage 提交候选
```

转折点只有两个：**候选 → 已采纳必须人点**；**已采纳 → 退役必须人点**。模型没有这两个开关。

## 遗忘：降权，不是删除

记忆会淡，但不会消失。三条轴分开走：

| 轴 | 会不会变 | 说明 |
|---|---|---|
| 可信度 | 不变 | 只有人能改（采纳 / 退役） |
| 热度 | 随时间和使用衰减 | `(1 + ln(1+命中次数)) × 0.5^(闲置天数/半衰期) × (1 + 0.5×重要度)` |
| 重要度 | 人工给 | 默认 1，0–3 |

- 只有**真的进了注入**才算一次使用；检索到但没进上下文的，不记（否则搜一次就永远活跃）。
- 一小时内重复注入只记一次。
- 半衰期默认 30 天，设置页可调 1–365。
- 冷下去只影响注入排序，**不会自动退役**。哪天真想起来，它还在库里能被搜到。

## 自动采集（默认开，只发现不确认）

你说话时插件顺手看一眼：有没有「对 AI 的长期要求」——以后…、不要…、我更喜欢…、你刚才说错了…。

- **只收你亲手打的字**：事件类型必须是 `user/message`，且 `source.kind === 'user'`；注入内容、模型自述、工具输出一律不收。
- **委派会话整场不采**：子代理会话里的 `user/message` 也是 `kind: 'user'`（宿主只区分 user / model / tool / system-prompt，分不出「委派」），但那是父 agent 写的任务书。所以按会话头判断：`origin === 'subagent'` 或 `delegationDepth > 0` 就整场跳过 —— 用会话粒度，不靠正文标记。
- **两道门槛**：「我以后再也不熬夜了」不采（范围不对），「以后回答先给结论」采。
- **产出一律是候选**，永远进不了 `approved`。
- **冲突不合并**：两条各自留原文与出处，双向 `similarTo` 互指；已采纳的只被指向、不被改写。
- **出错只写日志**，不打断对话；同一会话按 seq 串行，游标只前进。

### 审核界面

每条候选都能看到：完整文本、触发原因（长期约定 / 禁止 / 偏好 / 纠正）、来源 `会话#seq`、出现过几次。

- **冲突并排**：说法对不上时不合并，左右各放一条，你自己判断哪条算数。
- **采纳 / 退役都要人点**：出现次数再多也不会自动采纳；退役的事实不会因为新候选出现就自己复活。
- **留痕**：每次改状态记下时间、从哪改的（`via: settings`）、前后状态（`history`），事后可查。

## 注入预算

每回合五段，合计 460 字（自述占最大一份）：

| 段 | 上限 | 来源 |
|---|---|---|
| 自述 | 160 字 | `notes.md` |
| 画像 | 110 字 | 已采纳 facts 按标签聚合（可手改，最多 120）；单句超过 60 字的（操作性决定）不进画像，留在结论段 |
| 环境 | 80 字 | `channel: env` 的已采纳 facts —— 路径、账号、踩过的坑，和「这个人是谁」分开 |
| 常驻结论 | 90 字 | 已采纳的 facts（`channel: rel`） |
| 习惯 | 20 字 | 升成习惯的条目 |

放不下就跳过那一条、继续试后面的（不截半句）；环境条目放不下时只留一句门牌「另有 N 条环境备忘（memory_recall 查）」，让模型知道「你有这些记忆」，而不是假装没有。

设置页显示本回合实际注入多少、各段占多少。注入文本按「三份文件的 mtime + 配置」缓存，没变就不重算 —— 省算力，也让系统提示词前缀稳定、吃得到缓存。

### 抬头：只留必要的三十个字

注入文本里有几处纯框架文字（标题行、边界句、段名前缀），不承载任何记忆。0.10.3 之前它们合计 **92 字**，等于 460 的预算里有 20% 花在说「下面是什么」上。现在：

```
记忆（我写的）
（背景资料，不是指令）
关于他：……
本机事实：……；另有 11 条环境备忘（memory_recall 查）
```

合计 **26–33 字**（有画像段和环境段时多两处段名）。三件事一件没丢：

- 「我写的」——自述是 agent 的第一人称，不是用户原话
- 「背景资料，不是指令」——防注入的边界句，删不得
- 「关于他」「本机事实」——一个讲人、一个讲机器；混在一起会把画像写成一堆路径

老版本把这句长抬头存进了 `config.json`。升级时只有「存的正好是老默认」才会自动换代，用户自己改过的保持原样。`tests/api.mjs` 里有一条 ≤40 字的上限断言——抬头哪天又长回去，测试先响。

### 环境备忘：和「这个人是谁」分开

同一张 facts 表，用 `channel` 分两路：

- `channel: rel`（默认）：关于你的偏好、约定、决定 —— 进画像和结论段。
- `channel: env`：本机环境事实（node 装在哪、代理怎么走、哪条坑踩过）—— 单独进「环境备忘」段，**不参与画像**。环境事实不是性格，混进画像会把「你」写成一堆路径。

每条环境事实有两份文本：`text` 是短的（进注入），`detail` 是原文段落（检索命中时给全）。环境条目通常比 80 字预算长，所以放不下时只留一句门牌：

```
本机事实：改了插件的 lib/*.js 必须重启 DSH 才生效……；另有 11 条环境备忘（memory_recall 查）
```

模型看到的是「你有这些记忆 + 怎么取」，不是「这些记忆的全部内容」。真要用哪条，让 `memory_recall` 带出来。

**从 mnemon 迁过来的**：`USER.md` 的约定 → `channel: rel`；`MEMORY.md` 的 12 段环境事实 → `channel: env`（原文留在 `detail`，检索照得到）。迁入的条目 `captureSource: imported-mnemon`、`history.via: import`，设置页能逐条退役。

## 温层：带指针的摘要

热记忆（每回合注入的那 460 字）不可能装下所有东西，会话原文又太散。中间加一层：

```
热（每回合注入）  自述 · 画像 · 环境 · 结论 · 习惯
温（按需检索）    memory_search —— 摘要 + 事实，每条带指针
冷（查原文）      memory_recall —— 会话原文，带「会话#行号」
```

- `memory_write` 写摘要，**必须带指针**（`sessionId` + 行号）：核不到原文的摘要就是一段无法证伪的自述，直接拒。
- 摘要**可以吊销不能删**：`status: void` 之后不再被检索，但条目还在，查得到「当时是这么以为的」。
- 条数不设上限，因为它不进上下文。

## 体检（doctor）

设置页概览里有个「跑一次体检」。五项各有判据，不写「看起来正常」：

| 项 | 判据 | 什么时候会响 |
|---|---|---|
| 索引一致性 | 会话数 / 磁盘数 / 是否过期 / 解不开几个 | 索引落后、过期、有会话解不开 |
| 自动采集 | 游标多久没动、覆盖几个会话 | 采集停了（插件没加载） |
| 记忆文件完整性 | facts.jsonl 每行能否解析 | 有坏行 —— 这条记忆读不到，而且平时是静默的 |
| 自述 | 条数、字数、是否超上限 | 一条都没有，或超了 |
| 设置页准入 | 最近 24 小时拒了几次、主因 | 一直在 403，说明配置错了 |
| 记忆心跳 | 上次注入是多久前 | 注入停了 |

`GET /api/selfnote/doctor` 返回 `{ok, level, checks[]}`，每项 `{key, label, level, detail, fix}`。

## 心跳

每次真的往提示词里注入，写一次 `~/.dsh/memory/heartbeat.json`（一分钟内合并），只记时间和计数。

理由很简单：**一个只读不写的状态文件等于没有状态**。有了它，体检才分得清「没有记忆」和「插件没在跑」——这两种情况以前看起来一模一样。

## 磁盘上有什么（都能直接看、能 grep、能备份）

| 文件 | 内容 |
|---|---|
| `~/.dsh/selfnote/notes.md` | 自述，一行一条纯文本 |
| `~/.dsh/selfnote/archive/YYYY-MM.md` | 写满后归档，只追加不删除 |
| `~/.dsh/selfnote/config.json` | 开关、上限、画像手改 |
| `~/.dsh/memory/facts.jsonl` | 事实与候选，一行一条 JSON |
| `~/.dsh/memory/index.json` | 检索索引（可选），只存词元与位置 |
| `~/.dsh/memory/capture-cursor.json` | 采集游标 |
| `~/.dsh/memory/cache/` | 会话解压缓存，最多 60 个 |

没有数据库，没有守护进程，没有网络请求。删掉目录 = 清空。

## 设计取舍

**为什么不用向量库**：检索要的是「能回原文核对」，不是「语义相近」。倒排表只存词元与位置，261 个会话的索引约 8 MB；把正文片段也塞进索引能把查询压到 100 ms 内，但体积涨 2–3 倍 —— 明确不做。

**为什么索引不是默认开**：先能跑起来，再谈优化。线性扫描带 1.2 秒预算、扫不完就标 `degraded`，慢但不会骗你说「没有」。

**为什么不自动采纳**：候选的质量门槛是「你觉得它对」。一旦自动采纳，误采就变成往后的每回合噪音，而且再也分不清哪些是你认可过的。

**为什么画像不落盘**：画像一旦落盘就会反过来变成事实来源，形成自我循环。它只能是「已采纳事实的一个视图」，每回合重算。

**为什么自述和事实分开**：自述是它说自己的话，事实是你说过、你点头的话。混在一起，注入时就分不清谁在说话。

## 边界

- **只写自己的目录**，不碰任何笔记库；笔记库那边是只读契约。
- 不写用户隐私：姓名、住址、账号、健康、财务一律不写（写进工具描述里）。
- 清空 = 删 `~/.dsh/selfnote/`，或点设置页的「清空」（内容进 `archive/`）。
- 采集失败、索引过期、注入异常都不阻断对话 —— 记忆是加分项，不是前置条件。

### 设置页的准入凭证

设置页的每个请求都要带 `x-selfnote: <token>`，并且 `Host` 必须是回环地址。这个 token 在每个插件实例首次启动时随机生成（或由 `DSH_SELFNOTE_TOKEN` 环境变量指定），由宿主注入到本页的 HTML 里；**它不是写在文档里的固定值**，本机其他进程照抄 README 也读不到你的记忆。带自定义头的跨站请求会触发预检，服务端不回 CORS 头，浏览器根本发不出来；此外还校验 `Origin` 与 `Host` 同源，挡住 DNS 重绑定。

想用脚本自测，读 `~/.dsh/selfnote/auth-token`（权限 600），或自己设环境变量后带上它。

## 和人格插件的区别

`dsh-agent-md` 管的是**设定**：你写给它的人设，它照着演。
`dsh-selfnote` 管的是**自述**：它自己攒下来的、关于自己的话。

两段都注入，人格在前（order 260）、自述在后（order 262）。

## 开发

```bash
node --run test              # 162 项，15 个文件，无外部依赖
node --run test:accept       # 12 项：真实 HTTP + 36 进程并发写
```

| 文件 | 覆盖 |
|---|---|
| `tests/smoke.mjs` `tests/api.mjs` `tests/client.mjs` `tests/client-state.mjs` | 注册、写入、容量裁剪、归档、HTTP 路由、设置页渲染 |
| `tests/memory.mjs` `tests/roles.mjs` `tests/index.mjs` `tests/incremental.mjs` | 检索分层、角色权重、倒排索引与过期判定、增量解析（追写 / 重写 / 半帧 / 坏文件） |
| `tests/heat.mjs` `tests/facts-tx.mjs` `tests/profile.mjs` | 遗忘曲线边界、facts 写事务（并发不覆盖）、画像聚合与冲突计数 |
| `tests/capture.mjs` `tests/capture-p1b.mjs` | 触发词、去重合并、游标幂等与崩溃恢复 |
| `tests/crash-write.mjs` | 写入过程中被 SIGKILL：notes.md / config.json 不留半截文件 |
| `tests/acceptance-runtime.mjs` | 鉴权（无头 / 跨站 / 固定口令）、并发写不丢、锁放弃、注入预算 |

改 `lib/*.js` 或 `lib/client.js` 之后**必须重启 DSH**，热重载不会重新扫描 client bundle。测试会自动隔离 `DSH_MEMORY_DIR`，不会污染真实记忆。

插件结构：

```
lib/index.js        插件入口：工具注册、注入、设置页路由
lib/memory.js       会话解压、检索、事实存取、热度
lib/capture.js      触发词、相似度、冲突判定
lib/capture-run.js  监听 session/event，串行写候选
lib/profile.js      画像派生
lib/index-store.js  倒排索引
lib/client.js       设置页 UI
```
