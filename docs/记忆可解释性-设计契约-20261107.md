# 记忆可解释性 · 设计契约（2026-11-07，v1 已定稿）

> 来源：m05151 用户拍板三件事。本文件是「讨论」的产物，**不是实施计划**。
> 一句话：先让记忆系统知道自己做了什么，再让它知道哪些记忆已经失效，最后才让它学习在什么场景下使用哪些记忆。
> 用户原话：「尤其不要为了追求智能化，让记忆系统变成一个用户无法理解的黑箱。」

## 0. 本轮边界

- 本阶段**只做 A（可解释账本）**。
- C（有效期）、B（条件化）的契约在此**冻结、不实现**：A 上线后先「收集真实注入与跳过数据」，用观察结果再调 C，最后调 B。
- 按 writing-plans 的 Scope Check：A / C / B 是三个独立子系统，**各立一份实施计划，不合并**。
- 不改任何现有注入行为：A 只增加「解释」，不增删任何一条注入文本。

## 1. 三阶段与验收重点（按用户 m05151 原表）

| 阶段 | 工作 | 验收重点 |
|---|---|---|
| A | 可解释账本 | 每条未注入记忆都有明确原因 |
| C | 有效期机制 | 过期不注入、不删除、可续期 |
| B | 条件化 | scope 硬过滤，when 软加分 |

执行顺序：**A → 观察 → C → 观察 → B**。用户原话：「先完成 A，收集真实注入与跳过数据，再实施 C，最后利用 A 的观察数据调整 B。」

## 2. 四状态（C 的契约，先冻结）

| 状态 | 含义 | 允许注入 |
|---|---|---|
| 有效 | 尚未到期 | 是 |
| 已过期 | 超过 expiresAt | 否 |
| 已归档 | 用户主动退役 | 否 |
| 无期限 | 没有设置 expiresAt | 是 |

规则（用户逐条拍板）：
- 到期自动转为「已过期」，**不自动删除**。
- 过期条目仍可搜索、查看、编辑。
- 支持一键续期，可重新设置到期时间。
- 支持手动归档。
- 续期**不重置**创建时间、来源和历史记录。

两个维度必须独立：
- `expiresAt`：决定**能不能注入**。
- 半衰期：只影响**同类条目的排序权重**，不决定生死。

> 代码注记（勘察所得）：现有 `isExpiredNote(entry, ttlDays)` 按 temp 的 `date + TTL` 判过期，**没有 `expiresAt` 字段**；「退役」是 facts 的 `status`，自述的「归档」是 `deleteNote()` 写进 `archive/YYYY-MM.md` 的副产物。三处语义不同，C 开工前要先统一，别把「归档」当成同一个东西。

## 3. scope 粒度（B 的契约，先冻结）

- 第一阶段采用**手动项目标签**：`global` / `project:<名字>`，例 `{"scope": "project:dsh-wiki-notes"}`。
- `global`：全局记忆；`project:xxx`：指定项目记忆。
- 当前项目身份由运行环境**显式提供**。
- 没有可靠项目身份时**不得猜测匹配**；不确定当前项目时**只注入 global，不误注入项目记忆**。
- `scope` 不匹配时**直接排除**。
- **不要把当前工作目录名直接当作项目身份**。
- 未来可增加 Git 根目录自动发现，但它应是项目身份的**辅助识别机制**，不是记忆数据的唯一身份来源。

> 代码注记：插件目前完全不读 `process.cwd()` / `DSH_PROJECT`（已 grep 确认），`apply(ctx, config)` 也没有项目字段。第一阶段建议由 `config.project` 手填、默认 `''` =「无可靠身份 → 只注 global」；等 DSH 宿主真的传进来再接。C/B 开工前定。

## 4. 计数：暂不采用「救场」，只记客观事件（用户拍板）

只记两个口径：`injectionCount`（累计注入次数）、`lastInjectedAt`（最近一次注入时间）。

```json
{ "injectionCount": 12, "lastInjectedAt": "2026-11-07T00:00:00Z" }
```

**不采用**「注入后没有被纠正 = 这条记忆有价值」。用户给的四条反例逐条保留：模型根本没用到这条记忆 / 用户没注意到错误 / 用户接受了答案但答案其实不正确 / 记忆只是恰好与问题相关。未来若要做价值评估，应**独立设计用户反馈机制**，不从「模型没有被纠正」反推。

> 代码注记：`lib/memory.js:881 touchFacts()` 已记 `seenCount / lastSeen`（带 1 小时去重），语义是「被检索翻到过」，**不等于被注入**；两者必须分开。且 `composeInjection()` 命中 `injectCache` 时直接返回文本、不重跑 `assembleInjection()` —— 「注入次数」该按「文本真被返回给模型」计，缓存命中也算一次，需要单独挂钩。C 开工前定。

## 5. 三个工程约束（用户 m05151 逐条）

1. **skippedDetail 必须完整可追溯**：不只记录最终被跳过的条目，还要明确**每个 segment** 的处理结果。四种 reason 使用**封闭枚举**（`budget / expired / scope / duplicate`），不要随意增加第五种。
2. **多种跳过原因必须有确定优先级**：同一条可能同时过期、超预算、scope 不匹配。按**实际筛选流水线记录首次生效的排除原因**（first-match-wins），避免统计口径漂移。
3. **B 不得破坏现有全局记忆行为**：没设置 scope 的历史条目迁移时默认 `global`；没设置 when 的条目不应受到惩罚。

## 6. A 的落地：代码事实（本轮勘察）

- `segments` 共 **7 个**：`persona / notes / guide / profile / env / facts / habits`；`guide`、`profile` 的 `skipped` 恒为 `[]`（不按行打包）。按约束 1，**7 个都给 `skippedDetail`**，空数组也是明确结果。
- `skipped` 现在是**字符串数组**（被跳过的正文），不是对象；`parseNotes()` 只产出 `{date, text, tier, pin}`，**条目没有稳定 id**，`updateNote / setNoteMeta / deleteNote` 全按 index 定位。
- 注入期**没有去重逻辑**（`duplicate` 在 A 阶段没有产生源）。
- `/state` 的 `injectionState(inline, builtNow)` 每次单独重跑 `assembleInjection(cfg)`（**不带** spotlight）；真注入那遍**带** spotlight、且可能被 `injectCache` 命中。两遍不一定一致。
- `packNotes()` 现有流水线：`core` 直接排除 → `temp` 先判 `isExpiredNote` → `fitDetailed` 判 `budget`。

## 7. 三处已拍板（m05194，定稿）

| 决策 | 最终结论 | 补充约束 |
|---|---|---|
| D1：ID | 内容指纹派生 | **`normalize(text)` 必须在实施计划里逐步骤写明规范**，不能只写一个函数名；保证相同文本在不同调用中得到相同 ID，避免换行、首尾空白、Unicode 表示差异造成不必要的 ID 变化 |
| D2：core | 归入 `budget` | `preview` 必须是「素材层，不注入」；UI 与解释文本**不许只显示「预算不足」** |
| D2：流水线 | `scope → expired → duplicate → budget` | first-match-wins；A **不新增过滤行为**（不提前实现 scope、不引入 duplicate 去重，`duplicate` 只是预留枚举位） |
| D3：落盘 | 不落盘 | 仅实时 `/state` 与「注入」页折叠展示；**实时可解释性 ≠ 历史可追溯性**，A 只保证当前这一轮解释完整，不承诺跨轮查询历史跳过记录 |

D2 原文约束逐条保留：**不得为了生成解释信息而改变现有候选集合、排序、预算分配和注入文本**。

用户给 A 计划加的八条边界（逐条抄，不得在计划里做大）：
1. 只规划 A，不实现 C、B，也不提前修改它们的数据结构。
2. 保留 `notes.md` 原格式，不改变现有按 index 的增删改接口。
3. 7 个 segment 全部提供 `skippedDetail`，即使为空也必须显式返回。
4. 不改注入文本，必须通过**字节级回归测试**。
5. 不新增去重、有效期或项目识别逻辑。
6. 不新增跳过日志文件。
7. `/state` 与真实注入的解释数据必须来自**各自实际执行的那一遍**，不能拿预览结果冒充真实注入结果。
8. `injectionCount` / `lastInjectedAt` 必须以**真实注入文本返回**为计数依据，缓存命中也算；**不能使用 `seenCount` 或预览次数代替**。

最后一条的引申：**解释数据与注入计数是两个不同的观测口径，实施计划里分开设计、分别验收**（各自独立测试文件、独立断言）。

## 8. 验收锚（A 完成后要能当场回答）

- 12 条自述、预算 200 → 每条没进的都有**恰好一条**解释（允许同文撞 id，不查 id 唯一），且 `injection.text` 与改前**一字节不变**。
- 同时过期 + 超预算的一条 → reason 是 `expired`，不是 `budget`（first-match-wins 生效）。
- `core` 条目 → reason `budget`，preview 带「素材层」。
- 7 个 segment 全有 `skippedDetail`（含空数组）。
- 枚举外的值一个都不出现。
- `personaEnabled:false` 时 7 段齐全、persona 段零值，且 `overhead` 与改前基线完全相等。
- `preview` 按字素簇截断，不切开组合字符或 ZWJ emoji 序列；注入预算仍按码点计。
- 过期原因由 `packNotes()` 与 `skipped` 同源等长的 `skippedSources` 逐位给出，不靠尾部位置或文本比对猜。
- 同段两条相同文本都保留解释、两条 id 相同（内容指纹派生，不去重）。
