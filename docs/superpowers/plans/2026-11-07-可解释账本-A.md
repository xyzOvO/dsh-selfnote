> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. 执行方式已由用户 m05417 定为 **Native 串行**（明确否决 subagent-driven：五个任务共用 `lib/index.js`、有 CRLF 文件、注入文本需字节级一致）；Task 1 → 5 顺序执行，每任务独立提交，前一任务全绿才进下一任务。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `dsh-selfnote` 的每一条没进上下文的记忆，都在 `/state` 和「注入」页说明「被谁、因为什么挤掉」，并单独记下「注入文本真的返回给模型」的次数 —— 全程不改一个字节的注入文本。

**Architecture:** 解释数据由 `lib/explain.js`（纯函数）从**已有的** `segments[].skipped`、与它**同源等长**的 `skippedSources`（由 `packNotes()` 同一次构造产出，只作解释元数据）以及 `readNotes()` 原始数据事后推导，挂在 `assembleInjection()` 每次调用的返回值上，因此 `/state` 的预览那遍与真注入那遍各算各的、互不冒充；注入计数是另一条**独立**观测口径，唯一挂钩放在 `buildInjection()` 把文本交出去之前，落盘复用已有 `memory/state.json`。UI 只把 `skippedDetail` 折叠渲染出来，不参与任何筛选。

**Tech Stack:** Node >= 20.13.0、原生 ESM、`node:assert/strict`、`node:crypto` 的 `sha1`、`Intl.Segmenter`（grapheme 粒度，Node 原生）；无新依赖。测试沿用仓库的「纯 assert 脚本 + `console.log('N. …')`」风格，通过 `package.json:30` 的 `node tests/*.mjs &&` 串运行。

## Global Constraints

逐条抄自 Spec §7 与 m05194 用户原话，每个任务的验收都隐含本节：

- 只规划 A，不实现 C、B，也不提前修改它们的数据结构。
- 保留 `notes.md` 原格式，不改变现有按 index 的增删改接口（`appendNote / updateNote / setNoteMeta / deleteNote`）。
- 7 个 segment 全部提供 `skippedDetail`，即使为空也必须显式返回（空数组）。
- 不改注入文本，必须通过**字节级回归测试**。
- 不新增去重、有效期或项目识别逻辑。
- 不新增跳过日志文件；不建 `skips.jsonl`，不建跳过历史库。
- `/state` 与真实注入的解释数据必须来自**各自实际执行的那一遍**，不能拿预览结果冒充真实注入结果。
- `injectionCount` / `lastInjectedAt` 必须以**真实注入文本返回**为计数依据，缓存命中也算；**不能使用 `seenCount`、`hitCount` 或预览次数代替**。

- `reason` 是**封闭枚举** `SKIP_REASONS = ['budget','expired','scope','duplicate']`；冻结优先级 `SKIP_PRIORITY = ['scope','expired','duplicate','budget']`，first-match-wins；A 实际只跑 `expired → budget`，`duplicate` 只是预留枚举位、没有产生源，`scope` 不提前实现。
- `core` 条目归入 `budget`，但 `preview` 必须是字面量「素材层，不注入」；UI 与解释文本**不许只显示「预算不足」**。
- D2 原文约束：不得为了生成解释信息而改变现有候选集合、排序、预算分配和注入文本。
- D3：解释数据**不落盘**，数据流是「本轮注入计算 → 生成 skippedDetail → `/state` API → 「注入」页折叠展示」；实时可解释性 ≠ 历史可追溯性。
- D1：`normalize` 必须在实施计划里**逐步骤**写明规范（见 Task 1 Step 3），保证相同文本在不同调用中得到相同 ID，避免换行、首尾空白、Unicode 表示差异造成不必要的 ID 变化。

`normalizeForId` 的**六步规范**（m05194 硬要求，逐步骤写死，不许只留一个函数名）：

```js
export function normalizeForId(text) {
  const s1 = String(text ?? '')              // ① 非字符串/null 一律转字符串
  const s2 = s1.normalize('NFKC')           // ② 兼容等价 + 全角半角统一
  const s3 = s2.replace(/\r\n?/g, '\n')     // ③ CRLF / 裸 CR 统一成 LF
  const s4 = s3.trim()                       // ④ 去首尾空白
  const s5 = s4.replace(/\s+/gu, ' ')        // ⑤ 任何连续空白折叠成一个空格
  return s5                                 // ⑥ 纯函数：无 Date / 随机 / locale
}
export function contentId(text) {
  return createHash('sha1').update(normalizeForId(text), 'utf8').digest('hex').slice(0, 12)
}
```

`pickReason(flags)` 按 `SKIP_PRIORITY` 顺序找第一个 `flags[reason] === true`，全 false 返回 `null`；`SKIP_REASONS` 与 `SKIP_PRIORITY` 用 `Object.freeze`。`skippedId = segmentKey + ':' + contentId(text)`。

`previewOf` 按**字素簇**截（P2；`Intl.Segmenter` 在 Node >= 20.13.0 是原生全局，无需依赖）：

```js
const SEGMENTER = new Intl.Segmenter('und', { granularity: 'grapheme' })
export function previewOf(text, maxGraphemes = PREVIEW_MAX_CHARS) {
  const s = String(text ?? '')
  const parts = Array.from(SEGMENTER.segment(s), (part) => part.segment)
  if (parts.length <= maxGraphemes) return s
  return parts.slice(0, maxGraphemes).join('') + '…'
}
```

这把尺子**只用于展示**：`countChars()` 与六段预算仍按码点，不许把字素簇口径回灌预算，`PREVIEW_MAX_CHARS = 60` 的含义是「60 个字素簇」。

`describeSkipped` 是 A 的唯一分类算法（签名推不出来，故给全；**m05417 P1 后已删掉 `expiredCount` 与 `index >= skippedCount - expiredCount` 推断**）：

```js
// 只读取已有结果做「事后分类」，绝不重新打包、不改候选集合/排序/预算/文本。
function flagsFor(source) {
  return { scope: false, expired: source === 'expired', duplicate: false, budget: true }
}
export function describeSkipped({ key, skipped = [], sources = [], notes = [] }) {
  const list = Array.isArray(skipped) ? skipped : []
  // 来源数组必须同源等长；缺一项就整批保守降级，宁可少报原因也不报错原因
  const src = Array.isArray(sources) && sources.length === list.length ? sources : []
  const out = []
  list.forEach((raw, i) => {
    const text = String(raw ?? '')
    const reason = pickReason(flagsFor(src[i] ?? null))
    if (reason !== null) out.push({ id: skippedId(key, text), preview: previewOf(text), reason })
  })
  if (key === 'notes') {
    for (const e of notes.filter((e) => normalizeTier(e?.tier) === 'core')) {
      const text = String(e?.text ?? '')
      out.push({ id: skippedId(key, text), preview: CORE_PREVIEW, reason: 'budget' })
    }
  }
  return out
}
```

为什么不再依赖排列假设：`packNotes()` 把 `expiredTexts` 恒拼在 `skipped` 末尾（`lib/index.js:451-455`），但过期文本可能是**空串**（`expired.map(e => e.text)` 不经过 `fitDetailed` 的 `text === ''` 过滤）、可能与稳定条**文本相同**、可能重复，且 `notesSegment()` 门牌收敛（`:490-501`）最多重排三轮预算。按「末尾 N 条」或按文本比对都会误判。改由 `packNotes()` 在构造 `skipped` 的同一次调用里同步产出 `skippedSources[i]`（见 Task 2 Step 4），解释层只读这个平行数组；A 不新增筛选、排序、预算或文本，`ttlDays` 仍只由 `packNotes` 自己用。
