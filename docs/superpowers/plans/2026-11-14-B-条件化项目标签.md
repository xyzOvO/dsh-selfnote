# B 条件化项目标签 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task.

Status: **计划已立，契约冻结，本轮不实现**。执行顺序须在 C 完成并观察之后。

## Goal
给记忆条目加手动项目标签，使注入按显式项目身份筛选，而不是按工作目录猜。

## Architecture
标签值限定 `global` 或 `project:<名字>`；项目身份由运行环境显式提供；无法匹配当前项目的条目排除出注入；索引只存词元/角色/位置，不复制正文。

## Spec
- 写入/导入/编辑时保留项目标签。
- 当前项目身份缺失时，只注入 `global`。
- 不匹配当前项目的条目不注入，但可检索、可查看、可编辑。
- 不把工作目录名当项目身份；不自动猜项目。
- 解释账本需说明跳过原因是 scope，而不是 budget。

## Global Constraints
- 不改 C 的有效期语义；不改 A 的记账语义。
- 不重写已发布历史；兼容旧包缺标签默认值。
- 测试需覆盖标签往返、身份缺失、项目不匹配、跨项目检索。

## Review Focus
- 身份来源、默认值、迁移兼容、跳过原因与 UI 展示。
- 不扩大注入预算，不把条件化变成静默丢数据。

## Tasks
1. 写标签解析/往返/默认值失败测试。
2. 实现标签字段与显式项目身份传递。
3. 实现注入过滤与 skippedDetail scope 原因。
4. 实现设置页/检索页筛选与说明。
5. 全量回归、迁移兼容检查、文档与快照同步。

## Self-Review
确认每条「不匹配排除」都有对应「仍可检索」的断言。

## Execution Handoff
