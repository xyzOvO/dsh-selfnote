# C 有效期 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task.

Status: **计划已立，契约冻结，本轮不实现**。执行顺序须遵守 `A → 观察 → C → 观察 → B`。

## Goal
把当前半衰期只作为排序信号，新增显式有效期状态机：有效 / 已过期 / 已归档 / 无期限。

## Architecture
数据仍以 `facts.jsonl` 为源；`expiresAt` 决定能否注入；`memory_recall`/设置页必须如实显示状态；过期不自动删除。

## Tech Stack
Node.js ESM、现有 fact 字段、现有测试链。

## Spec
- 四条状态：有效、已过期、已归档、无期限；只有有效/无期限可注入。
- `expiresAt` 到期自动视为已过期，但保留原文、来源、历史与检索能力。
- 半衰期继续只影响同类排序，不决定是否可用。
- 续期不重置创建时间、来源或历史引用。

## Global Constraints
- 不改写已冻结契约；不改 A 的可解释账本字段语义。
- 每个状态迁移与边界都先写失败测试。
- 不加大注入预算；不删除用户数据。

## Review Focus
- 时区、闭区间/开区间、空值、历史纪录迁移。
- 设置页、注入解释、检索结果三处状态是否一致。

## Tasks
1. 写状态判定与过期边界失败测试。
2. 实现 `expiresAt` 读写/校验/状态映射。
3. 调整注入过滤与 skippedDetail 原因。
4. 调整设置页展示与筛选。
5. 全量回归、文档与快照同步。

## Self-Review
确认「过期不删除」「续期不重置来源」两条硬约束都有断言。

## Execution Handoff
待 A 的真实注入/跳过观察数据收集完成后，再单独执行本计划。
