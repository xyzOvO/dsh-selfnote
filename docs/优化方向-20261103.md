# selfnote 优化方向（2026-11-03，观察期结束）

> 依据：观察期实测数据 + agent-soul 的 ECHO 六层架构（`docs/ECHO-权威口径.md`）对照。
> 观察期已于 2026-11-03 结束，可以重新加功能。但两条硬约束**不因观察期结束而解除**：
> **① approved / retired 只能由人点；② 冲突永不自动裁决。**

## 一、现状快照（2026-11-03 实测）

| 指标 | 值 | 解读 |
|---|---|---|
| facts 总数 | 18（approved 3 / retired 15 / candidate 0） | 采集端在跑，但产出几乎全被判垃圾；现在没有新候选 |
| 采集来源 | auto 14 / manual 3 / user 1 | 自动采集是主力，但精度低（14 里活下来 1） |
| 注入 | 280 字 / 300（notes 119 / profile 40 / facts 47 / habits 0） | 头顶还有 20 字余量，习惯段空着 |
| 索引 | fresh **false**，301 已索引 / 308 磁盘，1790 条记录，9.98 MB | 落后 7 个会话；9.98MB 每次整份重写 |
| `/state` 延迟 | 726–1107 ms | 设置页像卡住 |
| 重建索引 | 同步阻塞 12.2 s | 期间对话僵死 |

## 二、对照 ECHO 六层：我们有哪几层

| ECHO 层 | 管什么 | selfnote 现状 | 缺口 |
|---|---|---|---|
| **L0** 时钟 + 心跳 | 现在几点、距上轮多久、未结 | **完全没有** | 记忆没有时间轴，无法形成叙事 |
| **L1** 自我 + 热记忆 | SELF.md 每轮注入 + 画像 | notes.md 自述 + 画像段 | **与 mnemon 的 USER.md / MEMORY.md 双重记账** |
| **L2** 工作台 | 当前上下文 | 不碰（DSH 自己的会话） | 正确，不该碰 |
| **L3** 一手层 | 会话日志，只追加 | 会话 zstd，只读，索引不复制正文 | ✅ 达标 |
| **L4** 索引 + 图记忆 | 摘要带指针 + 洞察关系边 | index.json 只存词元与位置 | 有索引，**无摘要、无温层检索、无图记忆** |
| **L5** 检索 + 门牌 | `memq` 四动词 + `log:<sid>#seq=N` | memory_recall 带 `会话#行号` | 门牌达标；**缺 facts 检索（温层）、缺 timeline** |

对照结论：**L3 / L5 已经达标，L1 有重叠风险，L0 完全空缺，L4 只有半截。**

## 三、五个方向（按该先做的顺序）

### P0 · 与 mnemon 划界（零代码，收益最大）

**问题**：mnemon 每轮注入 USER.md / MEMORY.md，selfnote 每轮注入自述 + 画像。同一种资源（"我是谁 / 用户是谁"）有两个权威源——这正是 agent-soul 判据里最硬的"双重记账"。

**做法**：定分工并写进两边文档与提示词。
- **mnemon = 环境事实**：机器、路径、账号、工具链、历史踩坑。客观、可验证、与对话无关。
- **selfnote = 交流关系**：怎么说、别说什么、长期约定、纠正过的偏好。主观、来自对话、需要人审。
- 判据一条：**"这句话换个 AI 来说还成立吗？"** 成立 → mnemon；只有在和这个人相处时才成立 → selfnote。

**效果**：消除将来的"两个说法我该信哪个"；自述预算的 120 字不再被环境事实挤占。

---

### P1 · `selfnote_doctor` 体检（可靠性）

**问题**：观察期最大的教训是**静默失败**——索引 fresh 报 false 只是卡片上一个词，坏会话只计个数，游标滞后没人看。soul 的坑 4 说得准：哨兵测的地方常常不是病灶出现的地方。

**做法**：一个只读工具，五项检查 + 一句话结论：
1. **索引一致性**：`builtAt` 与最近会话 mtime 交叉验证（防"状态文件没人写"）
2. **待同步**：`sessions vs disk` 差值 + 分别是哪几个会话
3. **采集滞后**：游标里每个会话的 seq 与磁盘最新 seq 的差
4. **数据完整性**：`facts.jsonl` 坏行、重复 id、approved 缺出处
5. **鉴权异常**：`auth.log` 里最近 24h 的 403 聚类（按 reason 分组）

**效果**：从"它可能在骗我"变成"它出错会喊"。五项每项都有明确判据，不报"看起来正常"。

---

### P2 · 性能三项（工程债，纯收益）

| 项 | 现状 | 做法 | 目标 |
|---|---|---|---|
| `/state` | 726–1107 ms | `listSessions()` 被扫 3 遍 → 扫一次 + 目录 mtime 缓存 | ≤100 ms |
| 重建索引 | 阻塞 12.2 s | 按会话分片，片间 `await setImmediate`，边建边报进度 | 不冻结对话；显示 187/305 |
| 检索命中的会话 | 868 ms | 解压结果 LRU 缓存（沿用 CACHE_VERSION） | 复查 ≤100 ms |

**效果**：设置页从"像坏了"变成"像正常软件"；重建索引时你能继续聊天。

---

### P3 · 温层检索 `memory_search`（记忆的成长性）

**问题**：approved facts 一旦超出 47 字预算就"存了但看不见"。硬盘能装，注意力装不下。

**做法**：新工具，在 facts + 自述 + 归档上检索，**遵守 ECHO 两条铁律**：
- **没有指针的摘要不许进结果** —— 每条必带 `factId` 与原始出处 `会话#行号`
- **只回指针 + 逐字片段，不做转述** —— 不生成"总结一下"，只给原文

评分沿用 wiki-notes 那套（标题 / 标签 / 正文词频），量小不需要 FTS。

**效果**：第 100 条记忆和第 3 条一样能被想起来；300 字不再决定"记住多少"。

---

### P4 · L0 时间层：心跳与未结（缺的那一层）

**问题**：selfnote 现在没有时间感。它不知道"上次注入是什么时候""哪些事说了还没做"。没有时间轴的记忆只能叫清单，不能叫成长。

**做法**（最小版，不铺开）：
- `heartbeat/YYYY-MM-DD.jsonl`：每次注入记一行（时间、段字数、命中哪些 factId）
- **未结清单**：从 facts 里带 `promise` 触发的条目派生（"下次""回头"这类），显示在概览页
- `doctor` 增加一项：心跳停更多久算异常

**效果**：可以回答"这条我什么时候说的、后来提过几次、有没有兑现"。这是从"存条目"到"有经历"的分界。

---

### 明确不做

| 不做 | 为什么 |
|---|---|
| 接管 DSH 的压缩 | 那是 soul 的 L2/换气层，碰了会和宿主打架；selfnote 只做外部记忆 |
| 图记忆 / 语义边 | mnemon 已经有记忆空间，重复造就是双重记账 |
| 摘要 + 指针（自造 L4 摘要） | 与压缩摘要职责重叠，收益存疑，等 P3 有数据再评估 |
| 自动采纳 / 自动冲突裁决 | 硬约束，永不做 |
